# v30.78 — Microsoft Graph / M365 Integration

## Umfang
Vollständige M365-Anbindung auf der bestehenden Connector-Runtime. Ressourcen:
Outlook Mail, Outlook Kalender, Kontakte, OneDrive, Teams, To Do, OneNote.

Eigenschaften: OAuth2 **Device-Code-Flow** (public client, kein Secret), Token-Refresh,
Incremental/Delta-Sync (Graph `@odata.deltaLink`), Batch-Requests (`$batch`, 20/Chunk),
Background-Sync, Memory-/Knowledge-Import über `ConnectorImportBridge`, Approval-Gate für
**alle** schreibenden Aktionen.

## Architektur (Wiederverwendung, kein Neubau)
- `ConnectorItem` (adapter_contract) als normalisierte Item-Grenze.
- `IncrementalSyncRunner` (incremental_runner) für Cursor-Commit + Fatal-Safety (kein Cursor-Commit bei fatalem Fetch-Fehler).
- `ConnectorImportBridge` (import_bridge) als idempotente Ingestion-/Memory-Grenze.
- `JsonCursorStore` (cursor_store) persistiert Delta-Cursor.
- `TokenRepository` + `TokenRefreshService` für Token-Persistenz/Refresh.
- Neuer Code liegt vollständig in `secondbrain/connectors/microsoft/` und ist stdlib-only.

## Netzwerk-Grenze / Testbarkeit
Sämtliche HTTP-I/O läuft über `transport.Transport`. Real: `UrllibTransport` (stdlib).
Tests: `FakeTransport` — kein Netz. 33 Offline-Tests, `pytest ... -q` grün, `compileall` grün.
Ein echter `m365-login` gegen Azure AD läuft nur auf deiner Maschine (Netz + App-Registrierung).

## Konfiguration (du legst die Azure-App an)
1. Azure Portal → App registrations → New registration → Accounts: „Personal + work/school".
2. Authentication → Advanced → **Allow public client flows = Yes** (Device Code).
3. API permissions (delegated): User.Read, Mail.ReadWrite, Mail.Send, Calendars.ReadWrite,
   Contacts.ReadWrite, Files.ReadWrite, Tasks.ReadWrite, Notes.ReadWrite, Chat.ReadWrite,
   ChannelMessage.Send, offline_access → Grant consent.
4. In `.env` eintragen:
   ```
   M365_CLIENT_ID=<Application (client) ID>
   M365_TENANT_ID=common        # oder deine Tenant-ID
   # M365_SCOPES=...            # optional, überschreibt Defaults
   ```
Ohne `M365_CLIENT_ID` liefert jedes m365-Kommando `config_error` mit klarer Meldung — keine Platzhalter-IDs.

## Launcher (Python 3.11+ Runtime, wegen datetime.UTC im Repo)
```
python launcher.py m365-login          # Device-Code; Code auf microsoft.com/devicelogin eingeben
python launcher.py m365-sync            # alle Ressourcen; --resources mail,calendar,todo
python launcher.py m365-status          # Auth-Status, Cursor, offene Approvals; --approve <id>
python launcher.py m365-disconnect      # Token + Cursor löschen
```

## Schreibende Aktionen (Approval-Pflicht)
Jeder Write (Mail senden, Termin/Kontakt/Task/Folder anlegen, Datei-Upload, Teams-Nachricht,
OneNote-Seite) läuft durch `ApprovalGate.guard`. Default = DENY: es wird ein `ApprovalRequest`
angelegt und `ApprovalRequired` geworfen. Erst nach `approve(request_id)` wird ausgeführt.
Persistenz: `runtime/connectors/m365_approvals.json`.

## Grenzen (bewusst)
- Teams-Nachrichten: Delegated-Scopes reichen für eigene Chats; org-weite Kanal-Historie braucht
  ggf. Admin-Consent / Application-Permissions — hier nicht aktiviert.
- OneNote/Teams nutzen Watermark bzw. Batch statt nativem Delta (Graph bietet dort kein Delta).
